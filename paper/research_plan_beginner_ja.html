研究計画書：メンタルヘルス支援対話ロボットの行動計画

非同期知識検索（RAG）と安全なジェスチャ生成を統合した、全二重音声対話ロボットの研究計画を、研究初心者にも読みやすい形で整理した HTML 版です。

研究段階
文献調査・設計計画段階。実装・ユーザ実験は未実施。
研究タイプ
臨床研究ではなく、工学システム研究＋非臨床のユーザ知覚評価。
最重要方針
診断・治療・薬剤助言・自律的危機介入は行わない。
この研究を一言で言うと：
メンタルヘルスに関する一般的な心理教育情報を、会話しながら安全に説明できるロボットを目指す研究である。ロボットはユーザの発話を聞きながら返答し、必要に応じて外部の知識ベースを検索し、発話内容に合った穏やかなジェスチャを出す。ただし、医師や心理職の代わりになるものではなく、危機的な状況では人間の専門職へつなぐ設計にする。

1. 研究の目的

本研究の目的は、メンタルヘルス支援の心理教育的対話を対象に、全二重音声対話、非同期 RAG、ジェスチャ計画、安全フィルタを統合したロボットシステムの設計と評価方法を示すことである。

目指すこと

  • ユーザの発話を聞きながら自然に応答する。
  • ストレス対処、睡眠衛生、リラクゼーションなどの一般的情報を分かりやすく伝える。
  • 発話に合った穏やかなジェスチャで理解を助ける。
  • 危険な出力を防ぎ、人間の監督につなげる。

目指さないこと

  • 精神疾患の診断。
  • 治療方針や薬に関する助言。
  • 症状改善や治療効果の主張。
  • 自殺・自傷などの危機への自律的介入。
  • 専門職の代替。

2. 研究背景

2.1 なぜメンタルヘルス支援ロボットなのか

メンタルヘルスに関する情報提供では、正確さだけでなく、話しやすさ、安心感、誤解を生まない説明が重要である。テキストチャットだけでなく、音声や身体動作を持つロボットを使うと、ユーザは「相手がいる」と感じやすくなる可能性がある。一方で、ロボットが人間らしく振る舞うほど、ユーザが過度に信頼したり、専門家のように誤解したりするリスクも高まる。

2.2 技術的な課題

課題初心者向けの説明本研究での対応
自然な会話 人間同士の会話では、相手の話を聞きながら相づちや返答準備をする。ロボットも一問一答だけでは不自然になりやすい。 全二重音声対話モデルを使い、聞くことと話すことを並行して扱う。
正確な情報 LLM はもっともらしい誤情報を出すことがある。メンタルヘルス文脈では特に危険である。 外部知識ベースを検索する RAG を使い、心理教育情報に基づく応答を目指す。
低遅延 検索を待ってから話すと、会話のテンポが悪くなる。 発話開始と検索を同時に進める「非同期 RAG」を使う。
身体動作の安全性 ジェスチャは分かりやすさを助けるが、危機的な相手に大きな動作を出すと不安を増やす可能性がある。 事前に登録した安全なジェスチャだけを Behavior Tree が選ぶ。

3. 関連研究の整理

文献調査は U1、U2、U7、U8、U9、U10 の 6 つの観点で整理されている。ここでは、研究初心者が全体像をつかめるように、各分野が本研究にどう関係するかを説明する。

3.1 全二重音声対話モデル

Moshi、AudioLM、dGSLM、LSLM、WavRAG などの研究は、音声をトークンとして扱い、リアルタイムに音声入出力を行うための基礎になる。特に Moshi 系の研究は「ユーザが話している間にもシステムが反応できる」方向を示す。ただし、MoshiRAG はプレプリント段階のため、確立済みの標準技術としてではなく、参考アーキテクチャとして扱う。

3.2 RAG と適応的検索

RAG（Retrieval-Augmented Generation）は、LLM の内部知識だけでなく、外部文書を検索して応答に使う方法である。FLARE や Self-RAG は「いつ検索するか」、Stream RAG は「生成と検索をどう並行させるか」を考える上で参考になる。本研究では、ユーザを待たせすぎないために、発話を始めながら検索も進める。

3.3 ロボット行動計画とジェスチャ生成

Behavior Tree は、ロボットの行動を「条件」と「動作」の木構造で管理する方法である。FSM より拡張しやすい場面があり、ロボット制御で使われてきた。本研究では、LLM が自由に動作を作るのではなく、Behavior Tree が安全確認済みのジェスチャだけを選ぶ構造にする。

3.4 音声とジェスチャの同期

ジェスチャは、発話中の重要な語句とタイミングが合っていると自然に見える。しかし、全二重音声生成のように発話が逐次生成される場合、どのタイミングでジェスチャを出すべきかの標準的な規範はまだ十分ではない。そのため、本研究ではまず工学的な設計値を置き、後でユーザ評価によって調整する。

3.5 HRI 評価とメンタルヘルス AI 安全性

HRI（Human-Robot Interaction）では、信頼、安全感、快適さ、自然さなどを質問紙で測る研究がある。本研究でも、臨床効果ではなくユーザ知覚を測る。また、メンタルヘルス AI では、機能境界、人間の監督、危機対応、プライバシー、透明性が重要である。

文献ユニット扱う領域本研究への接続
U1全二重音声 LLMリアルタイム音声対話の中核技術。
U2非同期・ストリーミング RAG検索遅延を抑えた知識参照。
U7行動計画・ジェスチャ生成Behavior Tree による安全な動作選択。
U8音声・ジェスチャ同期発話内容と身体動作のタイミング調整。
U9HRI 測定尺度安全感、信頼、快適さ、自然さ、理解度の評価。
U10安全・倫理機能境界、人間監督、危機時対応の設計。

4. 研究ギャップ

文献調査から分かることは、関連技術はそれぞれ存在するが、メンタルヘルス支援ロボットという安全性が強く求められる文脈で、それらを一つのシステムとして統合した研究が不足しているという点である。

ギャップ 1：全二重音声対話と RAG の統合

検索を待つと遅延が増えるが、検索しないと事実性が弱くなる。この両立が課題である。

ギャップ 2：安全なジェスチャ計画

メンタルヘルス支援文脈で、どの身体動作が安全かについて標準的な規範は十分でない。

ギャップ 3：統合評価

音声、検索、ジェスチャ、安全制約を合わせて、ユーザ知覚として評価する標準セットがまだ明確でない。

注意：このギャップは「世界初」と断言するためのものではない。現時点の調査範囲では十分に確認できない、という冷静な表現にとどめる。

5. 研究質問（Research Questions）

RQ問い評価の考え方
RQ1 非同期 RAG は、全二重音声対話の低遅延性を保ったまま、心理教育情報の事実性を高められるか。 検索遅延、応答開始遅延、検索結果と応答内容の一致、幻覚率、RAG なし条件との比較を見る。
RQ2 Behavior Tree による登録済みジェスチャ計画は、安全制約を守りながら文脈に合った動作を出せるか。 未登録動作が出ないか、危機時に動作が抑制されるか、緊急停止が機能するかを見る。
RQ3 ユーザは、提案システムを安全・信頼可能・快適・自然・理解しやすいと感じるか。 質問紙、理解確認、自由記述でユーザ知覚を評価する。臨床効果は測らない。

6. 具体的な手法

6.1 システム全体像

提案システムは 7 つのモジュールで構成する。初心者向けに言えば、「聞く・話す」「調べる」「判断する」「動く」「安全確認する」を分担させる設計である。

全二重音声対話

ユーザ音声を受け取りながら、ロボット音声を生成する。テキストトークンも出し、安全確認や検索に使う。

非同期 RAG

知識が必要な場面で、発話生成と並行して外部知識ベースを検索する。

心理教育知識ベース

ストレス対処、睡眠衛生、相談先案内など、診断や治療ではない情報だけを登録する。

対話・感情推定

現在が説明中か、共感が必要か、危機兆候があるかを推定する。詳細設計には追加文献調査が必要。

BT ジェスチャ計画

登録済みの安全なジェスチャから、状況に合うものだけを選ぶ。

音声・ジェスチャ同期

発話の重要語句に合わせてジェスチャを開始する。

安全フィルタ

診断・薬剤助言・危機対応などの危険な出力を止め、人間監督へつなぐ。

6.2 データの流れ

  1. ユーザがロボットに話しかける。
  2. 音声対話モジュールが音声応答を作り始める。
  3. 知識が必要だと判断した場合、RAG モジュールが知識ベースを検索する。
  4. 検索結果が間に合えば、応答の情報提示部分に反映する。
  5. 対話状態と感情状態を推定し、ジェスチャ計画に渡す。
  6. Behavior Tree が安全なジェスチャコマンドを選ぶ。
  7. 安全フィルタが発話と動作を監視し、必要なら抑制・停止・人間への接続を行う。

6.3 ジェスチャ語彙の例

種類例使用場面安全上の注意
beat小さな手のリズム動作説明の強調大きく速い動きにしない。
deictic画面や資料を示す情報提示人を指差すような動作は避ける。
iconic呼吸やリラックス動作を表す心理教育治療行為に見えない表現に限定する。
neutralうなずき、静止、穏やかな姿勢傾聴、危機兆候時危機時はこの集合に制限する。

7. 評価計画

評価は、技術として動くか、安全に振る舞うか、ユーザがどう感じるか、の 3 種類に分ける。ここで重要なのは、臨床効果を評価しないことである。

評価対象指標成功の見方
技術評価（RQ1） 非同期 RAG と音声応答 応答開始遅延、検索遅延、検索結果の反映率、幻覚率 RAG なしより事実性が改善し、遅延が許容範囲に収まる。
行動・安全評価（RQ2） ジェスチャ計画と安全制約 未登録コマンド率、危機時抑制、緊急停止、同期ずれ 安全制約違反がなく、文脈から大きく外れない。
ユーザ知覚評価（RQ3） 非臨床参加者の印象 知覚安全性、信頼、快適さ、自然さ、情報理解、自由記述 音声＋ジェスチャが不安や違和感を増やさず、理解しやすさを改善する可能性を示す。
ユーザ実験の前提：ユーザ知覚評価を行う場合は、倫理審査、参加者説明、同意取得、危機兆候が出た場合の対応手順、データ保護方針を事前に整える必要がある。

8. 安全・倫理設計

本研究では、安全性を後付けの注意書きではなく、システム構造に組み込む。具体的には 6 層の安全要求を置く。

層安全要求実装上の意味
Tier 1機能境界診断、治療、薬剤助言を出力しない。
Tier 2危機検知とエスカレーション危機兆候では人間専門職や適切な相談先へつなぐ。
Tier 3Human-in-the-loop専門職が監視、介入、停止できる。
Tier 4ジェスチャ安全危機時は能動的動作を抑え、穏やかな中立動作に限定する。
Tier 5プライバシー音声・対話ログを機微情報として扱う。
Tier 6透明性ロボットが AI であり、できること・できないことを事前に説明する。

9. 実用性・実現可能性・研究意義に関する冷静な評価

観点評価コメント
技術的実現可能性 中程度 個別技術は存在するが、全二重音声、非同期 RAG、ジェスチャ同期、安全フィルタを安定して統合する難度は高い。まずは限定ドメイン・短い対話シナリオで検証するのが現実的である。
実用性 限定的 現段階で医療現場にそのまま導入するのは不適切である。一方、心理教育情報の案内、セルフケア情報の説明、相談窓口への誘導など、低リスク用途では将来的な可能性がある。
研究意義 高い 音声対話、知識検索、身体動作、安全制約を同時に扱う点に意義がある。臨床効果ではなく、工学的統合と HRI 評価に限定すれば、研究として成立しやすい。
リスク 高い 誤情報、過信、危機対応の失敗、プライバシー侵害、ジェスチャによる不安増大があり得る。安全要求を満たせない場合は、ユーザ実験へ進むべきではない。
新規性 中〜高 個別技術の新規性ではなく、メンタルヘルス支援文脈での統合設計に新規性がある。ただし、MoshiRAG など未査読プレプリントに依存しすぎる表現は避けるべきである。
客観的コメント： この研究は、すぐに実用化できる医療ロボットを作る計画ではない。むしろ、危険な過大主張を避けながら、低遅延対話、知識検索、ジェスチャ、安全制約をどのように統合できるかを検証する基礎的な工学研究である。実用化を語るには、技術評価、倫理審査、専門家レビュー、長期的なユーザ評価、運用体制の検討が必要である。

10. 今後の方針

10.1 直近の作業

  1. U5・U6 の追加文献調査：対話フェーズ検出と感情認識の根拠を補強する。
  2. 知識ベースの範囲定義：心理教育情報だけを対象にし、診断・治療・薬剤情報を除外する。
  3. ジェスチャ語彙の設計：安全確認済みの小さな動作集合から始める。
  4. 安全テストケースの作成：診断要求、薬剤相談、危機兆候などの入力に対する拒否・エスカレーションを確認する。
  5. 最小プロトタイプの実装：音声対話、RAG、BT、ログ記録を小さく統合する。

10.2 段階的ロードマップ

段階内容完了条件
Phase 1追加文献調査と要件定義M4 の根拠、安全要求、評価指標が文書化される。
Phase 2オフライン検証スクリプト入力で RAG、拒否応答、ジェスチャ選択が確認できる。

Phase 4非臨床ユーザ評価倫理審査後、知覚安全性・信頼・理解度などを測定する。
Phase 5論文化工学評価とユーザ知覚評価を、過大主張なしで報告する。
